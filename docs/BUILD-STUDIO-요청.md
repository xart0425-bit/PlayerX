## 한 줄 요약

**계획 → 만들기 → 배포까지는 잘 굴러갔는데, 그 다음이 없습니다.** 배포한 뒤에
실제로 써 보면서 고치는 일이 계속 생기는데, 그게 계획서에도 개발 현황에도
들어갈 자리가 없습니다. 그래서 손으로 6단계를 만들어 넣었습니다.
이걸 BUILD STUDIO 가 원래 갖고 있으면 좋겠습니다.

## 왜 이 요청을 드리는가 — 이 프로젝트에서 실제로 있었던 일

PlayerX 는 계획서의 5단계를 모두 끝내고 배포판까지 나왔습니다 (45개 작업 전부 완료).
그런데 그 뒤에 아래 일들이 **줄줄이** 나왔습니다.

| 실제로 나온 일 | 성격 |
|---|---|
| 계획서의 화면 목업이 UI 로 옮겨진 적이 없었다 | 계획과 결과물의 불일치 |
| 타임라인을 끌면 한참 뒤에 따라온다 | 써 봐야 아는 문제 |
| 비교 탭 첫 열기에 2초가 걸린다 | 써 봐야 아는 문제 |
| 영상을 어떻게 여는지 못 찾겠다 | 써 봐야 아는 문제 |
| 재생 중 글자가 1px 씩 떨린다 | 써 봐야 아는 문제 |
| 구간만 반복 재생하고 싶다 | 뒤늦게 생긴 요구 |

**하나도 미리 적을 수 없는 것들입니다.** 계획을 잘못 세워서가 아니라, 다 만들어
써 보기 전에는 알 수 없는 종류라서 그렇습니다. 지금 워크플로에는 이걸 받아 줄
칸이 없어서, 이 일들은 대화 기록에만 남고 문서에는 안 남습니다.

## 요청 1 — "다듬기" 단계 (가장 중요)

`계획` · `만들기` · `배포` 옆에 **`다듬기`** 를 하나 놓아 주세요.
누르면 이런 일을 하면 됩니다.

1. **무엇이 바뀌었는지 묻는다** — "이번에 뭘 고치셨나요 / 뭐가 불편했나요"
2. **`docs/PROGRESS.json` 의 마지막 단계에 항목을 덧붙인다.**
   기존 스키마 그대로면 됩니다:
   ```json
   { "id": "6-9", "label": "타임라인 그리기 10.2ms → 0.27ms", "done": true, "tag": "성능" }
   ```
   - 새 단계를 만들 때는 `{ "no": 6, "name": "다듬기와 보강", "note": "...", "tasks": [...] }`
   - **못 고친 것도 `done: false` 로 남깁니다.** 지우면 없던 일이 됩니다.
3. **`docs/BUILD-LOG.md` 맨 위에 경위를 적는다** — 특히 **실패한 시도**.
   안 되는 길을 다음 사람이 또 걷지 않게 하는 유일한 방법입니다.
4. **계획서가 현재 물건과 어긋났으면 같이 고친다** — 기능이 늘었으면 6절(핵심 기능),
   화면이 바뀌었으면 8절(화면 구성).

이번에 손으로 만든 6단계가 그 결과물입니다 (`docs/PROGRESS.json` 참고).
개발 현황 화면은 손대지 않아도 그대로 잘 그려집니다 — 스키마를 그대로 썼습니다.

## 요청 2 — 목업을 만들기 단계가 실제로 보게 해 주세요

이번 프로젝트에서 제일 크게 어긋난 부분입니다.

`화면 목업` 으로 만든 그림은 `docs/mockups/` 에 저장되고 계획서에 이미지 한 줄로
붙습니다. **그런데 `만들기` 단계는 그 그림을 보지 않습니다.** 그래서 1~5단계가
전부 끝나고 배포판까지 나온 뒤에야 "목업이 반영이 안 됐다"는 걸 알았습니다.
UI 를 통째로 다시 입히는 작업이 뒤늦게 생겼습니다.

두 가지 중 하나면 충분할 것 같습니다.

- **만들기 단계의 각 단계 끝에서** 목업과 실제 화면을 나란히 놓고 확인하는 절차
  (스크린샷을 찍어 비교하는 것까지는 자동화가 어렵더라도, "목업과 다른 점이
  있는지" 를 묻기만 해도 이번 같은 일은 안 납니다)
- 또는 **계획서에 목업이 있으면, 만들기 단계의 작업 목록에 "목업 반영" 항목을
  자동으로 넣기**

## 요청 3 — `.buildstudio/status.json` 이 1단계에서 멈춰 있습니다

```json
{ "kind": "build", "step": 4, "label": "1단계 완료 — 재생과 프레임 이동", "done": true, ... }
```

5단계까지 다 끝났는데 이 파일은 1단계 완료 상태 그대로입니다.
개발 현황 화면이 한동안 "3단계 — 비교 모드가 지금 차례" 라고 잘못 알려 줬습니다
(그때 이미 3~5단계가 다 끝나 있었습니다).
스키마를 몰라 손대지 않았습니다 — 단계가 끝날 때마다 갱신되게 해 주세요.

## 참고 — 이 프로젝트가 쓰고 있는 규칙

같이 정해서 `docs/BUILD-PLAN.md` 9절에 적어 뒀습니다. 다듬기 단계를 만드실 때
참고가 될 것 같아 옮겨 둡니다.

1. 고친 것·못 고친 것을 그때그때 현황에 적는다. 못 고친 것도 남긴다.
2. **수치로 말할 수 있는 것은 수치로 적는다** (`10.2ms → 0.27ms`).
   느낌으로 적으면 다음에 또 느려졌을 때 비교할 기준이 없습니다.
3. 경위와 **실패한 시도**를 로그에 적는다.
4. 계획서가 현재 물건과 어긋나면 계획서를 고친다.
